# Police Chase P0.4 — reserva AI dedicada

## O que muda

A P0.4 requer o core AssettoServer apontado pelo submodule deste projeto. Atualizar somente `PoliceChasePlugin.dll` não instala a nova política de reserva.

O core testado está publicado no fork `ArthurMCarlos/AssettoServer`, branch `codex/p0.4-dedicated-police-ai`, commit:

```text
c2d9d1e360071bd5ea54254b6bf3c21c7681bdd9
```

O `CAR_12` passa a manter exatamente um `AiState` fora da distribuição dinâmica. O spawn ainda é nativo: ele ocorre depois que um jogador termina de carregar e o `AiBehavior` encontra um ponto seguro.

## Build e instalação

Inicialize o submodule fixado pelo projeto e compile o servidor modificado:

```powershell
git submodule update --init --recursive
dotnet build external/AssettoServer/AssettoServer/AssettoServer.csproj -c Release
```

Instale o build Release do AssettoServer conforme o processo já usado pelo servidor. Depois compile e atualize também o plugin:

```powershell
dotnet build PoliceChasePlugin.sln -c Release
```

O artefato do plugin permanece:

```text
artifacts/PoliceChasePlugin/PoliceChasePlugin.dll
```

Não misture a nova DLL do plugin com o executável original do AssettoServer 0.0.54: a reserva mínima está implementada no core modificado.

## Configuração preservada

O slot continua configurado manualmente como na P0.3:

```ini
[CAR_12]
MODEL=mlgz_skoda_octavia_2019_police
SKIN=Oryx_White
AI=FIXED
```

E o plugin:

```yaml
Enabled: true
PoliceCarSessionId: 12
PoliceCarModel: "mlgz_skoda_octavia_2019_police"
```

Não é necessário aumentar `AiPerPlayerTargetCount`, `MaxAiTargetCount`, `TrafficDensity` ou `MaxSpeedKph`.

## Resultado esperado do cálculo

Com dez slots de tráfego, um policial reservado e um jogador:

```text
AI Slot overbooking update - No. players: 1 - No. AI Slots: 10 - Reserved AI Slots: 1 - Target AI count: 10 - Overbooking: 1 - Rest: 0
```

O resultado final é:

- `CAR_0..CAR_9`: dez instâncias de tráfego, como antes;
- `CAR_10..CAR_11`: slots de jogadores, sem alteração;
- `CAR_12`: uma instância policial reservada;
- total: dez instâncias dinâmicas mais uma reservada.

## Quando o carro aparece

O `CAR_12` não precisa estar visível durante o boot. O lifecycle esperado é:

1. O plugin cria e reserva o estado policial.
2. Um jogador termina de carregar e se torna elegível.
3. O `AiBehavior`, atualizado duas vezes por segundo na configuração padrão, procura um ponto seguro.
4. O spawn nativo inicializa e posiciona o `CAR_12`.
5. Recalcular o overbooking não reduz mais o target policial para zero.

O log `Police AI waiting for native spawn` é um snapshot feito antes do posicionamento. A ausência posterior de `Police AI initialized` não significa, sozinha, que o spawn falhou; a P0.4 ainda não possui um observador contínuo dessa transição.

## Validação no servidor real

1. Confirme que o servidor executa o commit do core fixado no submodule.
2. Confirme `PoliceCarSessionId: 12` e `AI=FIXED` no `CAR_12`.
3. Inicie o servidor e conecte um jogador.
4. Aguarde o jogador terminar de carregar e alguns ciclos do `AiBehavior`.
5. Verifique que `CAR_0..CAR_9` continuam ativos.
6. Verifique que o `CAR_12` aparece e não desaparece após novos recálculos de overbooking.
7. Verifique que `CAR_10` e `CAR_11` continuam disponíveis para jogadores.
8. Verifique RandomWeatherPlugin, AI Traffic e colisões normais.

## Fora de escopo

A P0.4 ainda não implementa perseguição, velocidade dinâmica, sirene, HUD, Heat, Wanted, teleporte comandado pelo plugin ou pathfinding próprio.
